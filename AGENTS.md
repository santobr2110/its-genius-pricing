
- Observability pricing has two isolated models (classic UM bands vs levels M1–M4 + NVPS) selected by `modeloObservabilidade`; only one ever produces monitoring cost — keeps saved pricings unchanged.
- Shared pricing lives in `src/lib/pricing/`: every offering computes the markup-divisor cascade through `cascataNucleo` with its own declared `REGRA_*` edge rule (Σ ceiling, divisor form, sum order) — rules reproduce historical results and must not be harmonized. Tax rates for every offering come only from `tax_product_codes`/`tax_product_code_rates` (via `useTaxCodes` + `resolveTaxRates`, UI in `ProdutoFiscalCard`); the legacy static/localStorage code table was removed — one official source, managed in Admin ("Cadastro tributário de produtos"). Each code carries `ofertas`  and `ProdutoFiscalCard` takes an `oferta` prop to list only codes tagged with that offering (a code may serve several; untagged codes appear nowhere); `catalog_products` is deprecated — one product/tax registry, no duplicates.
- `src/test/naoRegressao.test.ts` snapshots Smart ITO, BodyShop and M1–M4 results; never update those snapshots to make a change pass — protects existing pricing.
- Treinamento catalog (courses, proposal content, combos, params) lives in `training_*` tables, read via `useTreinamentoCadastro`, gated by `page.trn.view` (read) / `page.trn.admin` (write) in RLS; pure helpers in `src/lib/treinamento/` — keeps official course data and pending-confirmation flags in one auditable place.
- Treinamento pricing: pure engine in `src/lib/treinamento/calc.ts` + `carrinho.ts` (tested in `treinamentoCalc.test.ts`); drafts/quotes live in `pricing_presets` with group `observabilidade`/offering `treinamento` via `useTreinamentoCotacoes` (Smart ITO's `usePricingPresets` left untouched) — avoids regressions in existing offerings.

- Treinamento: o SKU fiscal de cada condição de venda (Turma Aberta, In Company, Somente exame) fica em `training_params` (`produto_*`), editado em Financeiro › Impostos & Markup, não no cadastro do curso — a condição é escolhida em cada venda.
- Subscrições Zabbix (preço fixo por SKU) calcula o valor de chegada via `decomporVenda` em `src/lib/pricing/chegada.ts`; `aplicarDesconto` do Treinamento é um wrapper fino dele, provado equivalente em `chegadaEquivalencia.test.ts` — uma só conta de chegada para as duas ofertas.
- Subscrições Zabbix catalog (SKUs, proposal content, params) lives in `zabbix_*` tables, read via `useZabbixCadastro`, gated by `page.zbx.view` (read) / `page.zbx.admin` (write) in RLS; pure helpers in `src/lib/zabbix/calc.ts` — mirrors the Treinamento pattern so each offering stays isolated.
